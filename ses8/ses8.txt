Poor features bottleneck everything downstream. So, what is feature engineering? Feature engineering is the process of selecting, transforming, or creating input variables to improve the performance of a machine learning model. Recall that a supervised model is just a function y equals to f of x. X is the explanatory variables. Y is the target. Feature engineering is everything we do on the x side of that variable before the models use it. A concrete example, sales prediction. The raw data might give us a date and a product ID. Just two columns. The date and product ID are not directly meaningful to the model. A better feature set derived from the same raw data is the day of week, holiday or not, season, and product category. Each one is a richer, more directly predictive signal than the raw timestamp or ID. Feature engineering is a concept of making a machine learning model with such features that seem more related to the target variable to build a better model. Why is feature engineering so important? Three reasons. To boost model performance, to prevent overfitting, and to make your model more interpretable. One important caveat, feature engineering is fundamentally trial and error. There is no single recipe that works for every data set. In this lecture, we will cover the general techniques you can try across different problems. Feature engineering breaks down into four main types. The first is transforming features, reshaping existing variables so the model can use them better. Transforming includes scaling, log transformation, and encoding categorical variables into numbers. The second activity is creating features, building new variables from existing ones, either by crossing them or by using domain knowledge. There are two more types, extracting features, compressing a large set in a smaller one like PCA, and selecting features, removing columns where the input dimension is too large relative to the data. These are also part of feature engineering. For this lecture, our focus in the highlighted pair, transforming features, and creating features. Next, transforming numerical variables. Before diving into concrete transforming method, let us explain about what types of variables exist in the first place. You need to understand what kind of input variables exist to apply the right transformation that depends on the variable type. There are two broad categories. Quantitative data, also called numerical variables, and qualitative data, also called categorical variables. Within quantitative data, the ratio scale is the most informative. Differences have meaning, and there is a true zero. Body weight, 50 kilos or 70 kilos, and distance, 2 km or 200 km, are ratio scale examples. Saying twice as heavy is meaningful because zero is a fixed reference. The interval scale also has meaningful differences but no true zero. Temperature in Celsius, 50°, 30°, and year, 2000 or 2025, are interval scale. The gap between values is meaningful, but twice as much is not. You can't say, for example, 30° C is two times hotter than 15° C. Within qualitative data, the ordinal scale has a meaningful order, like academic grades, A, B, C, or survey responses, good or bad. The nominal scale has only distinct categories with no natural order. Nationality, Japanese, Chinese, or product ID. This four-way split, ratio, interval, ordinal, nominal, is what tells us which transformation makes sense for which column. Now, let's look at the transformations themselves, starting with numerical variables. The first transformation is scaling. When features differ greatly in scale, the larger scaled feature can have an undue influence on the model. For example, if one feature is income in dollars, ranging up to millions, and another is age, 0 to 100, a distance-based model will be dominated by income. The first scaling method is standardization. Rescale so the mean is zero and the standard deviation is one. The formula is X minus its mean divided by its standard deviation. The histogram on the right shows that the shape of the distribution is preserved. Only its location and width change. The second method is normalization. Also called min-max scaling. Rescale so the minimum is zero and the maximum is one. The formula is X minus the minimum of X divided by the maximum of X minus the minimum of X. Same idea, different reference points. The next transformation is log transformation. The log compresses large values and stretches small ones which makes it easier for the model to see relationship across orders of magnitude. Log transformation is especially useful when the distribution is heavily skewed. Many small values and a few very large ones like income. One important caveat. Log is not defined for zero or negative values. So you either apply it only to strictly positive quantities or you can use log of 1 plus X for example when the data contains zeros. In Python from sklearn.preprocessing import StandardScaler for standardization and MinMaxScaler for normalization. Both have fit transformed. For log transformation just call np.logx. That's all there is to the implementation. One subtle, but important point, scaling has almost no effect on tree-based models. The reason is that trees split on the rank order of feature values, not the absolute scale. Scaling doesn't change the magnitude relationship between the two values. Tree-based methods, such as decision trees, give us essentially identical results before and after standardization. Scaling still matters, though, for methods including regression models. Let's go back to the video part. >> Next, transforming categorical variables. The first method is label encoding. Assign each distinct category a unique integer. For example, red for one, green for two, blue for three. So, our color column of red, green, blue, green, green, red becomes 1 2 3 2 2 1. Label encoding is simple and works fine with tree-based models. A tree can split between any pair of integers. The catch is that it introduces a fake ordering. The model might think that blue with value three is somehow greater than red with value one. For linear or distance-based models, the fake order can mislead the model. The second method is one-hot encoding. Create a separate column for each category and assign one to the column that matches. The same color column becomes three new columns. Color red, color green, and color blue. Row by row, the matching column gets a one and the rest gets zero. So, red becomes 1 0 0. Green becomes 0 1 0, and blue becomes 0 0 1, and so on. The full encoded table has one one per row and zeros everywhere else. One-hot encoding's merit is that it removes the fake numerical relationship. Every category is treated asymmetrically. The demerit is high memory consumption. For a high cardinality variable, like product IDs with thousands of distinct values, you get one column per category, which can blow up memory and lead to overfitting. The next idea is cross features, also called interaction features. A new feature built from a product or other combination of two or more existing features. For example, A, B, C can be transformed into A * B, A * C, B * C, and A * B * C, and so on. A classic case is rent prediction. Rent is high when room size is large and distance to station is small. The model needs the product of these two, which a simple model cannot easily learn on its own. On the left, there is a 2D scatter of two normalized leaf features. The two classes occupy opposite corners. Leaf length and width is alone cannot separate them with a single line. But, if we add a new column, length times width, and look at the single column instead, the picture changes. The product column separate the two classes cleanly with a single threshold. The red horizontal line shows that everything above some cutoff is class zero and everything below is class one. A linear model can now solve the problem trivially. Cross features capture interactions that simple models cannot learn on their own, which is their merit. The demerit is that the number of possible cross features grows combinatorially, so they cause memory and can lead to overfitting if you make too many. Ensemble learnings is a method to improve your models performance by combining multiple models. The basic idea prepare multiple models then aggregate the predictions. By majority vote for classification or by averaging for regression. The diagram on the right show the pattern. Input goes into N classifiers C1, C2, and CN. Each produces an output O1, O2, ON. We combine them into final output. The majority tends to beat any single model because the individual mistakes cancel out. Two main families dominate practice, bagging and boosting. We will cover both in this section. Bagging stands for bootstrapping aggregating. Step one, take the training data. Step two, generate many bootstrap resamples of it. A bootstrap resample is a draw of N samples from the original training set with replacement. So, duplicates are allowed. Repeat that B times to get B different resample data sets. Each resample data set is slightly different from the others because the random draw picks different rows. Step three, train a one separate model on each resample. We end up with B trained models. Each individual model is a little weaker because it only saw noisy subset of the data. But the combined model aggregated by vote or average is often much stronger. That is bagging in five steps. Resample, train, repeat, aggregate. Why does bagging work? The intuition is the wisdom of the crowd. A graph on the right plots majority vote accuracy against the number of independent voters each with 60% accuracy. A single expert at 60% accuracy gives, unsurprisingly, 60% overall accuracy. Five independent voters, each at 60%, push the majority vote accuracy up to about 68%. 11 voters reach out 75%. 101 voters reach about 98. 100 imperfect models can outperform a single strong one if their mistakes are diverse. The big caveat, if every voter makes the same mistake, voting does not help at all. The diversity of mistakes is what makes the math work. A famous example of bagging is a random forest. Bagging is applied to decision trees, but with one extra twist. Without it, every tree would tend to look at the same. A single strong feature would always be picked for the first split. The extra twist is that at each split, only a random subset of M features is considered as candidates. That forces the tree to look different from each other. We train many such trees and take the average. That is a random forest. Let's see bagging in action. Please scroll to section 5.2.
